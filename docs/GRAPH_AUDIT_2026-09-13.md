# 법령 그래프 최초 저장·검수 기록

## 저장 결과

기존 PostgreSQL의 현행·시행된 법령을 읽어 비어 있던 Neo4j에 저장했다.
원문 재수집·임베딩 갱신·사용자 문서 접근은 하지 않았다. GraphRAG는 false로 유지한다.

| 항목 | 결과 |
|---|---:|
| 법령명 수 | 27 |
| 조문 노드 | 3,789 |
| 원문에서 연결 가능한 인용 후보 | 944 |
| 중복 정리 후 저장된 CITES 관계 | 873 |
| 미해결 참조 | 1,483 |

동일 출발/대상/정규화 참조를 가진 후보는 MERGE로 합쳐진다.
따라서 944와 873의 차이는 저장 누락이 아니다. 노드는 조 단위이며 항·호·목은 관계 속성이다.

## 자동 검수

scripts/audit_law_graph.py로 PostgreSQL의 현재 예상 그래프와 저장 그래프를 전체 대조했다.

- 조문 누락·과거 버전 노드·중복 노드: 각각 0
- 관계 누락·예상 밖 관계·중복 관계: 각각 0
- 원문에 없는 근거 문구·대상 조 번호 불일치·하위 항목 존재 검증 실패·상태 불일치: 0
- 첫 감사 연결은 WSL 재기동 시점에 ServiceUnavailable로 실패했으며, Neo4j healthy 확인 후 재실행해 통과했다.

이 결과는 저장·파서 기준 정합성이다. 생성기와 감사기가 같은 참조/본문 파서를 재사용하므로
공통 파서 오류를 독립적으로 증명하지 못한다. 최신 공식 법령과의 전수 대조나 세무 정답률 평가가 아니다.

## 원문 문맥 표본 20건 검토

출발/대상 법령 조합, 항 참조 여부, 가지번호 여부를 구분한 20건을 확인했다.
저장 원문에 인용이 존재하고 표시된 대상 조문과 대응했다. 예시:

- 지방세법 제103조의17 → 소득세법 제149조
- 소득세법 제26조 → 국세기본법 제52조
- 소득세법 제26조 → 조세특례제한법 제106조의2 제2항

발견한 제한:

- `제146조제1항 및 제2항`은 명시적으로 파싱된 첫 참조만 포함한다. 생략 목록의 후속 항은 누락된다.
- `같은 법 제150조 및 제151조`처럼 법령명이 생략된 후속 참조는 연결되지 않는다.
- 지방세특례제한법 시행령 제74조의 표 형식 원문에 줄/칸 구분이 섞여 있다. 명시적 인용 일부는 추출됐지만
  전체 문맥 복원·표 파싱 품질이 보장되지 않는다.
- 인용 자체가 질문에 적용 가능한 근거라는 의미는 아니다. 위임/예외/준용 관계로 확정하지 않는다.

## 미해결 원인

| 분류 | 건수 | 해석 |
|---|---:|---|
| 적재 가능 현행 스냅샷에서 대상 없음 | 1,236 | 미수집·미래/불명확 시행일 제외·법령명/조문 불일치 등을 추가 분류해야 함 |
| 대상 호 검증 실패 | 246 | 실제 호 부재·저장 원문 누락·파서 한계 구분 필요 |
| 대상 항 검증 실패 | 1 | 원문과 파서 대조 필요 |

대상 부재 후보 중 조세특례제한법 시행령 268건, 소득세법 시행령 60건 등이 있다.
이는 해당 법령 전체가 없다는 뜻이 아니라, 이번 적재 가능 스냅샷에서 요청 대상이 확인되지 않았다는 뜻이다.
파서가 아예 추출하지 않는 생략 참조는 위 미해결 집계에 포함되지 않는다.

## 재검증과 조회

```bash
docker exec tax_backend python scripts/audit_law_graph.py
```

위 명령은 읽기 전용이다. 상세 JSON 결과와 문맥 표본을 출력하고 정합성 오류 시 종료 코드 1을 반환한다.

Neo4j Browser에서 관계도를 보려면:

```cypher
MATCH (s:TaxArticle)-[r:CITES]->(t:TaxArticle)
RETURN s, r, t LIMIT 50
```

다음 단계는 미해결 1,483건의 상세 원인 분류와 관계 추출 품질 평가다.
GraphRAG 활성화 전 기존 RAG와 검색·인용·답변 품질 및 지연시간을 비교해야 한다.

# GraphRAG 구현·실행 검증 — 2026-09-19

## 결론

기존 RAG에 선택형 Neo4j 검색 확장을 연결하고 실제 데이터를 동기화했다.
서비스는 `GRAPH_RAG_ENABLED=false`를 유지한다. 관계 저장 성공과 답변 품질 개선은 별개이며,
이번 검색 평가에서는 추가적인 정답 조문 발견을 입증하지 못했다.

## 실행 환경과 방법

- WSL venv 활성화 후 `bash dev/docker-up-wsl.sh backend frontend neo4j`로 기본 Compose를 재빌드했다.
- 실행 중인 Ollama 생성·Qwen3 Embedding 4B/2560차원 v1 구성을 보존했다. llama.cpp 전환·모델 다운로드 없음.
- 전체 백엔드: `docker exec tax_backend pytest -q` → **431 passed, 2 skipped, 26 warnings, 5 subtests passed**.
- WSL 격리 Neo4j: `python -m pytest -q tests/integration --run-neo4j --graph-real-sample` → **2 passed**. 합성/공개 원문 표본의 실제 Cypher 저장·조회·중복 방지·관계 교체, 역방향 조회 확인.
- 비활성·장애·시간 초과 fallback, 과거 질문 제외, PDF/해석례 seed 제외, 원문·정의 버전 확인, 단일/복수 일반 검색 연결, 약칭 범위, 역방향 계열 제한, 긴 추가 본문 제외를 테스트한다.
- 프런트엔드 경유 `/api/health/ready`, `/api/health/dependencies` HTTP 200 확인. 이는 전체 의존성/답변의 품질 보증이 아니다.
- WSL 재기동 직후 Neo4j 준비 전 조회는 한 차례 연결 거부가 있었고, 준비 후 재검증에 성공했다. 애플리케이션 확장은 이런 장애에서 기존 RAG로 복귀한다.

## 실제 검색 비교

명령: `docker exec tax_backend python scripts/eval_graph_rag.py`

기존 `tests/eval/golden_qa.json`의 정답 조문번호가 있는 **38문항**을 사용했다.
정답 세목 필터를 입력하고 질문 하나로 기본 검색을 한 뒤, 동일 결과에만 Graph 확장을 적용했다.
새 무작위 사용자 ID를 사용해 기존 사용자 PDF를 읽지 않았다. 서버의 플래그는 변경하지 않았고
평가 프로세스 내부에서만 true/false를 바꿨다. 새 정답을 모델이나 검색 결과로 자동 생성하지 않았다.

| 최종 실행 지표 | 결과 |
|---|---:|
| 기본 top-5에서 기존 라벨 조문 발견 | 38/38 |
| Graph 확장 후 같은 top-5에서 발견 | 38/38 |
| 최대 7개 전체에서 발견 | 38/38 |
| 추가 조문이 붙은 질문 | 23/38 |
| 확장 평균 소요 시간 | 0.118초 |
| 추가 본문 최대 / 평균 | 3,639자 / 약 1,208자 |

문항별 질문·순위·추가 근거·시간·본문 길이는 [실행 결과 JSON](evaluations/graph_rag_2026-09-19.json)에 보존했다.
첫 확장은 1.828초였으며 평균은 콜드 상태/캐시/장비 부하에 영향받는다. 운영 지연 SLO가 아니다.

첫 실험은 31/38문항에 확장했고 다른 세목의 역방향 인용, 긴 본문이 섞였다.
동일 계열 역방향 제한·일반 질문 표현 제외·추가 본문 4,000자 제한 후 재실행한 값이 위 최종 결과다.
같은 평가셋을 보고 규칙을 보완했으므로 독립 holdout 검증으로 소개하지 않는다.

## 한계와 다음 작업

1. 단일 정답 조문 중심의 기존 평가셋은 이미 기본 검색에서 모두 발견된다. 법률+시행령+시행규칙을 함께 요구하는 별도 정답 근거 집합을 전문가 검수로 구축해야 한다.
2. 키워드 중복은 질문 적합성 보증이 아니다. 예를 들어 `inc-02` 기본공제 질문에도 양도소득 관련 시행령이 보충된다. 같은 법령 계열 안의 세목/공제 목적 혼입을 평가해야 한다.
3. 실제 생성 답변·세무 계산 정답·프런트엔드 도구 경로는 이번 A/B에 포함하지 않았다. 질문 분류/멀티쿼리 생성도 우회했다. 38/38은 세무 답변 정답률이 아니다.
4. 기본 top-5와 확장 최대 7개의 개수 차이가 있다. 동일 토큰 예산의 정밀도, 전체 필수 근거 재현율, 잘못된 추가 근거 비율, 생성 인용의 정확성을 함께 측정해야 한다.
5. 4,000자 제한은 추가 본문만 대상으로 한다. 기본 RAG 자체에 2만 자가 넘는 사례가 있어 모델 전체 컨텍스트 예산 관리가 별도 필요하다.
6. 후보 24개는 결정적 순서로 제한한다. 인용이 많은 조문의 관련 후보가 컷 밖으로 밀릴 수 있으므로 후보 선별/시드 배분도 다음 평가 대상이다.
7. Neo4j 상태 API, 프런트엔드 관계 배지/원문 경로 표시, 실서비스 활성화는 후속 작업이다. 검증 전 기본 비활성을 유지한다.

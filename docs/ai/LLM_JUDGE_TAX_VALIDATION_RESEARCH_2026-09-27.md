# 기존 LLM Judge를 활용한 세무 정확성 검증 연구

작성: 2026-09-27. 범위: 저장소 코드·저장 결과·연구 원문 조사 및 확장 설계. 아래 신규 실행기·스키마·지표는 제안이며 이번 조사에서 구현하거나 유료 모델 평가를 실행한 결과가 아니다.

사용자 결정: 운영자 평가는 LangSmith에서 진행한다(ADR-058). 사용자 채팅에는 해당 답변의 근거·확인 상태를 표시한다. 구현 순서는 백엔드 구조화 검사 결과 → SSE 진행/최종 결과 → 채팅 근거 패널 → LangSmith 평가 연결이며, 서비스 내부 관리자 대시보드는 이번 범위에서 제외한다.

## 결론

기존 자동화 기반을 확장하면 세무 답변의 항목별 평가를 상당 부분 자동화할 수 있다. `evaluation/judge.py`의 항목별 구조화 판정과 증거 ID 검증을 유지하고, `kg_relation_judge.py`의 독립 모델 설정·재개·사용량 기록을 답변 평가에도 적용한다. 모든 신규 답변을 두 전문가가 전수 채점하는 방식보다, 기준 표본과 모호한 사례를 사람이 검수하고 나머지 반복 평가는 교정된 Judge가 처리하는 방안을 권한다.

다만 자동 판정의 통과율과 실제 정확도는 별도로 보고해야 한다. 기존 실행에서 Judge의 잘못된 통과가 이미 관측됐기 때문이다. 이번 연구의 우선 과제는 Judge 호출 추가보다 **평가에 필요한 입력을 완전하게 연결하고, 잘못된 답변을 통과시키는 빈도를 측정하는 것**이다.

## 1. 확인한 구현과 실행 기록

|---|---|---|

| `evaluation/QUALITY_CRITERIA.md` | R1/R2/G1/G2/A1~A6/T1 총 11항목, 중대 오류·분모·반례·A/B 설계 | 평가 항목과 보고 계약 |

저장 파일을 직접 확인한 결과:

- `evaluation/runs/judge-evidence-ids-01/judge.json`: Qwen3.5:9b, 합성 행동 사례 1개, 3항목 pass. 세무 정답 3건이라는 뜻은 아니다.
- `evaluation/runs/precedent-pilot-20260922/experiment.json`: Qwen3.5:9b, 판례 사례 5개, 10항목 중 pass 6/fail 3/error 1. 당시 분석 문서에는 공식 판결요지와 모순된 설명을 pass 처리한 사례가 기록돼 있다. 해당 분석은 AI 보조 대조이며 인간 확정 골드는 아니다. 60% 세무 정확도로 해석할 수 없다.
- `evaluation/runs/kg-relation-final-20260926.json`: Luna, 관계 56개, consensus supported 48/unsupported 8. 이는 모델 판정 분포이며 56/56 정답이라는 의미가 아니다. 관계 검수 문서와 인간 검수 양식은 아직 독립 인간 골드가 없는 상태를 기록한다.
- `evaluation/datasets/answer_pilot.json`: 5개 모두 dev/draft 및 `recorded` 어댑터다. 기준·반례 후보가 있지만 공식 원문 컨텍스트와 승인은 미완료다.

과거 Qwen 판정 결과로 현재 Luna의 답변 Judge 성능을 추정해서는 안 된다. Luna로 수행한 관계 판정도 세무 답변 평가와 과제가 다르다.

## 2. 실제 코드의 연결 공백

1. **Judge의 입력이 부족하다.** `judge.assess()`는 질문, `case.input.context`, 답변, 루브릭 지시문, 증거 정책을 보낸다. `observation.payload.context`의 실제 검색 컨텍스트, 계산 관측, `review_card.required_claims/forbidden_claims/calibration_examples`는 자동으로 보내지 않는다. 루브릭 문장에 직접 들어간 내용은 보지만 카드 전체를 읽는 구조가 아니다. 따라서 현재 구조만으로 실제 근거 충실성과 독립 정답 일치성을 동시에 평가할 수 없다.
2. **증거 ID는 의미를 보증하지 않는다.** 현재 검사는 ID 존재·중복·필수 증거·전체 답변 범위를 확인한다. R3에 적힌 명제를 반대로 해석하면서 R3을 선택해도 형식 검사를 통과할 수 있다. 실제 판례 진단이 이 위험을 보여준다.
3. **평가 경로와 서비스 경로가 다르다.** `adapters.live()`의 `answer_fixed_context`는 여전히 `_append_source_list_if_missing`와 `apply_citation_guard`를 호출한다. 현재 작업 트리의 일반/SSE 채팅은 사후 출처 보정 없이 `guarded_answer`로 보류한다. 평가기를 먼저 맞추지 않으면 개선 전 동작을 측정할 수 있다. 과거법령 `history_answer` 경로 역시 수집 범위에 명시해야 한다.
4. **독립 모델·배치 기능이 답변 Judge에 부족하다.** 일반 `judge.evaluate()`는 기본 채팅 provider/model을 상속하고 마지막에 보고서를 쓴다. KG Judge에 있는 전용 설정·카드별 재개·사용량 추적을 옮길 수 있다. 두 구현을 통째로 복사하기보다 공통 배치 실행기를 추출하는 편이 낫다.
5. **기준서의 항목 전체가 실행되는 것은 아니다.** 일반 Judge는 `stage=answer`인 관측의 루브릭만 실행한다. 출력 집계는 전체 verdict 횟수이며, 11항목별 대시보드·사례 최종 판정·판정 범위·Judge 대 인간 일치도는 통합돼 있지 않다. `not_applicable`과 `missing_claim_ids`도 현재 답변 Judge 출력 스키마에 없다.
6. **행동 평가 정책이 특정 사례에 묶여 있다.** `evidence_policy()`의 예외는 합성 사례 1개와 3개 항목 ID에 고정돼 있다. 원문 없는 정보 부족 질문에서 재질문 행동을 일반적으로 검사하려면 항목 스키마에 정책을 선언해야 한다.
7. **표준 CLI에는 제한이 있다.** `judge`는 승인되지 않은 카드·원문 없는 카드를 unknown으로 처리하고 종료 코드 2를 반환한다. 판례 파일럿만 `diagnostic_draft=True`를 명시한다. 자동 배치는 실행 완료, 판정 불가, 품질 실패를 보고서로 구분해야 하며 종료 코드만으로 모델 오류라고 분류하면 안 된다.
8. **LangSmith 지표 전송은 미연결이다.** 기존 bridge는 scorer의 결과를 읽으며 `judge.json`의 항목 판정을 자동 전송하지 않는다. 자동 Judge를 붙였다고 기존 인간 gate가 바뀌는 구조도 아니다.

## 3. 연구에서 가져올 원칙

- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)는 긴 답변을 개별 사실 주장으로 나누어 출처의 지지를 측정한다. 이 프로젝트에서는 조건·예외·부정·시점을 유지한 원자적 세무 주장과 답변 위치를 연결하는 방식으로 적용할 수 있다. 사실 지지율만으로 필요한 설명의 누락까지 측정할 수는 없으므로 별도 완전성 검사가 필요하다.
- [ALCE](https://aclanthology.org/2023.emnlp-main.398/)는 답변의 품질과 인용 지원을 평가한다. 이 프로젝트에서는 인용 존재, 해당 인용의 주장 지지, 필요한 주장에 대한 인용 누락을 각각 측정하는 근거로 삼는다.
- [ARES](https://aclanthology.org/2024.naacl-long.20/)는 문맥 관련성·답변 충실성·답변 관련성을 분리하고 인간 표본으로 자동 판정의 오류를 보정한다. 이 프로젝트에도 소규모 기준 표본 + 대규모 Judge 평가가 적합하다. 논문의 미세조정 모델·통계 절차를 그대로 구현한 상태는 아니며, 한국 세무 성능은 별도로 검증해야 한다.
- [MT-Bench의 Judge 연구](https://arxiv.org/abs/2306.05685)는 위치·장황함·자기 선호 편향과 추론의 한계를 다룬다. 생성과 평가 모델 설정을 분리하고, 모델명·실험 방식을 숨기며, 쌍 비교에는 순서 교환을 적용한다. 다른 모델 두 개가 동의해도 오류가 통계적으로 독립이라는 뜻은 아니다.
- [법률 RAG 실증 연구](https://arxiv.org/abs/2405.20362)는 법률 도구에서도 오류와 응답성의 별도 측정이 필요함을 보여준다. 이 연구의 타 서비스 수치를 본 프로젝트의 오류율로 옮기지 않는다. 현재 출력 보류를 늘리는 변경은 정답 제공률·불필요한 보류율과 함께 평가해야 한다.

## 4. 제안하는 파이프라인

```text
버전이 고정된 평가 카드 + 공식 원문 스냅샷
  → 실제 서비스 경로 실행과 관측 저장
  → 코드로 출처·조항·시점 메타데이터·산술 검사
  → 답변 주장 분해 및 원문 위치 연결
  → 항목별 Judge + 중요 항목 독립 재판정
  → 불일치/중대 오류/표본 인간 검수
  → 항목별 지표·Judge 오답 통과율·회귀 보고서
```

### A. 서로 다른 두 종류의 근거를 입력한다

- **실제 생성 근거:** 사용자가 제공한 사실, 최종 검색 컨텍스트, 도구 결과, 계산 입력·결과, 그래프 추가 근거. 답변이 무엇을 보고 만들어졌는지 검사한다.
- **독립 기준 근거:** 평가 카드의 적용 시점·필수 주장·금지 주장·관련 공식 원문·예외·기대 계산값. 검색기가 잘못 가져온 자료에 충실한 오답을 잡는다.

두 근거 집합의 역할을 프롬프트와 필드로 구분한다. 생성기에 독립 정답·반례를 전달하지 않는다. 독립 기준이 없는 새 질문은 근거 충실성 진단은 가능하지만 정답 정확도는 unknown으로 둔다. Judge가 추가 검색할 경우 검색 결과의 출처·버전·원문을 스냅샷으로 기록하고, 발견한 자료를 곧바로 승인 정답으로 바꾸지 않는다.

### B. 주장과 적용 조건을 함께 판정한다

답변의 각 핵심 주장에 `claim_id`, `answer_span_ids`, 대상·조건·시점·결론, `evidence_ids`, 연결된 필수/금지 주장 ID를 기록한다. 단순 문장 분리는 하나의 문장에 섞인 올바른 명제와 틀린 명제를 구별하지 못한다. 분해 결과에서도 예외나 부정 표현이 유실될 수 있으므로 전체 답변 범위와 미연결 문장도 보존한다.

판정은 supported/contradicted/insufficient를 사용하고 항목 pass/fail/unknown으로 집계한다. 판단 이유는 짧은 근거 설명과 정확한 위치로 남긴다. `missing_claim_ids`로 필수 주장 누락을 별도 검사한다. 관계가 애매하거나 법령 적용을 확정할 자료가 없으면 unknown을 유지한다.

| 기존 ID | 판정할 내용 | 권장 판정 방법 |
|---|---|---|
| R1/R2 | 필수 조문 확보와 잘못된 근거 채택 | 버전·조항 ID 대조 + 기준 라벨 |
| G1/G2 | 관계 원문 무결성과 질문에 대한 기여 | 기존 KG 검사 + 질문별 Judge |
| A1 | 대상·조건·결론의 기준 일치 | 독립 기준 근거와 주장별 대조 |
| A2 | 각 설명이 실제 생성 근거에 있는가 | 실제 컨텍스트에 대한 지지·모순 판정 |
| A3 | 결론을 바꾸는 조건·예외를 빠뜨렸는가 | 필수 주장 ID 전수 대조 |
| A4 | 인용이 존재하며 해당 설명을 지지하는가 | 코드의 존재 검사 + 의미 Judge |
| A5 | 사건일·귀속기간·경과규정이 맞는가 | 버전 검사 + 적용 조건 Judge |
| A6 | 정보 부족에 적절히 재질문했는가 | 사전 answerability 기준과 비교 |
| T1 | 입력·단위·금액·절사 순서가 맞는가 | 독립 기대값과 결정적 계산 비교 |

T1의 산술 정답은 LLM 투표로 결정하지 않는다. 계산기가 쓴 입력이 사실관계와 맞는지, 공제 자격과 규정 선택이 적절한지는 A1/A5에서 함께 검사한다.

### C. Judge 구성과 오류 처리

답변 Judge에 평가 전용 provider/model/추론 예산/timeout을 둔다. 구체적 모델의 우열은 기존 반례 및 별도 검증 표본으로 비교한 후 정한다. 기존 KG_JUDGE 설정 방식은 재사용하되 관계 Judge와 답변 Judge의 과제·보고서는 구별한다.

첫 Judge가 전체 항목을 평가하고, 두 번째 Judge는 결론·시점·금액 관련 중요 항목, 충돌 사례, 무작위 통과 표본을 독립적으로 평가한다. 두 번째 호출에 첫 번째의 점수·이유를 먼저 보여주지 않는다. 불일치는 다수결로 덮지 않고 검토 대상으로 남긴다. 두 Judge 합의에 대해서도 인간 표본과 대조한다.

모델의 자기 보고 confidence를 정확한 확률로 취급하지 않는다. 형식 오류 재시도와 법적 판단 충돌을 구분하고, 예산 초과·429·원문 없음은 별도 상태로 남긴다. 관련 없는 근거를 제거할 때도 핵심 조건·예외가 누락되지 않았는지 기록한다.

### D. 보류 정책의 효과까지 측정한다

평가 관측은 서버 내부에서 `raw_answer`, `final_answer`, `guard_result`를 구분한다. raw 답변은 평가 전용 합성·공개 사례의 로컬 결과로 보관하며 사용자 화면에 보내지 않는다. 사용자의 실제 민감 문서를 자동으로 외부 평가 모델에 보내는 흐름은 이 설계에 포함하지 않는다.

- 근거와 필수 입력이 충분한 질문: 최종 보류는 유용한 정답 제공 실패로 집계한다.
- 필수 정보가 부족한 질문: 올바른 보류·재질문은 A6의 성공이다. 설명 정확도 항목은 사전에 정한 적용 규칙에 따라 N/A 또는 unknown으로 기록한다.
- raw는 오답이지만 final이 보류: 생성 오류와 차단 성공을 둘 다 기록한다.
- raw와 final 모두 오답: 사용자에게 도달한 중대 오류로 별도 기록한다.

이 구분이 없으면 모든 질문을 보류하는 서비스가 높은 정확도를 얻는 평가가 된다.

## 5. 항목별로 보고할 수치

각 항목·세목·시점 유형마다 pass/fail/unknown/error/N/A 원시 건수를 저장한다.

- **Judge 판정 통과율:** P/(P+F). 모델의 판정 비율이며 실제 정답률로 표시하지 않는다.
- **판정 범위:** (P+F)/(P+F+U+E). N/A 적용 여부는 실행 전에 정한다.
- **Judge 오답 통과율:** 인간 fail 사례 중 Judge pass 비율. 중대 항목은 별도 집계한다.
- **통과 답변의 잔여 오류율:** Judge pass 사례 중 인간 fail 비율. 위 오답 통과율과 분모가 다르다.
- **정답 오차단율·미판정률:** 인간 pass에 대한 fail/unknown/error를 구분한다.
- **최종 정답 제공률·정당한 보류율:** 답변 가능/불가 기준별로 측정한다.
- **운영 지표:** 사례당 Judge 호출 수·입출력 토큰·제공자 비용·지연·재시도 수. 비용 미제공은 null로 둔다.

변형 질문과 반복 호출은 같은 원 사례 그룹에 속한다. 이를 독립 표본 수로 부풀리지 않는다. 분포를 대표하는 무작위 감사 표본과 오류를 찾기 위한 집중 검수 표본을 구별한다. 후자만으로 전체 서비스 정확도를 추정하지 않는다. 통계적 구간 추정은 표본 선정·그룹 의존성을 반영하며 ARES의 보정 방법은 후속 후보로 둔다.

## 6. 구현 순서와 완료 기준

1. **서비스와 관측 일치.** `adapters.py`의 오래된 guard 호출을 정리하고 `precedent_pilot.collect()`를 일반화한다. 일반/SSE/과거법령 경로와 raw/final·도구·최종 컨텍스트가 재현 가능하게 수집돼야 한다. 고정 근거 실험과 전체 검색 실험은 별도 표시한다.
2. **입력·스키마 확장.** `schema.py`/`judge.py`에 독립 기준, 실제 컨텍스트, 주장 ID, 누락 주장, 항목별 적용성·증거 정책을 추가한다. 기존 카드·run의 hash를 깨지 않도록 새 데이터셋 버전을 만든다.
3. **알려진 실패로 교정.** 기존 판례 5건과 오답 통과 기록부터 원자적 기준으로 분해한다. 정상 설명, 결론 반전, 주체 교환, 예외 삭제, 시점 변경, 금액 변경, 답변 내부 모순을 대조 사례로 만든다. 자동 변형 라벨도 의미 보존을 확인하기 전에는 draft다. 이 자료는 개발용으로 고정한다.
4. **평가 전용 배치.** KG Judge의 설정·원자적 저장·재개·재시도·사용량을 공통화하고 출력 hash·코드 revision·dirty diff 식별자·정책 버전을 기록한다. 성공한 항목은 같은 조건에서 중복 과금 없이 재사용한다.
5. **Judge 교정 보고서.** 새 답변 Judge scorer가 항목별 혼동행렬·오답 통과율·잔여 오류율·판정 범위를 낸다. 초기에는 검수 가능한 작은 기준 표본을 전수 확인하고, 규모 확대 후 불일치 전수 + 통과/실패의 무작위 표본 감사를 적용한다. 핵심 법적 판정은 독립 검수 후 확정하고 해석 충돌은 미판정으로 남긴다.
6. **회귀 및 표시.** 알려진 중대 오류가 다시 통과하면 해당 변경을 차단한다. 실제 정확도 주장은 별도 holdout에서 인간 기준과 대조한 범위에 한정한다. 기존 인간 gate는 유지하고 자동 Judge gate를 별도 결과로 추가한다. LangSmith에는 `judge.*`, `human.*`, `mechanical.*`를 구분해 연결한다.

모든 사례를 처음부터 사람에게 맡길 필요는 없다. 카드 초안·원문 연결·오답 후보 생성·반복 실행·항목 판정·실패 분류·변경 전후 비교를 자동화하고, 기준 확정·Judge 교정·충돌 해결에 사람의 시간을 집중한다. 인간 기준이 없는 동안에도 자동 진단과 회귀 비교는 즉시 진행할 수 있지만 결과 명칭은 Judge 판정으로 유지한다.

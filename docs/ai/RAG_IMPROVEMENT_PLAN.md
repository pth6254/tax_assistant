# 추가 RAG 개선 제안

정리일: 2026-10-01. **이 문서는 후속 설계안이며 구현 완료 기록이 아니다.**
현재 동작과 검증 결과는 [CURRENT_STATUS.md](CURRENT_STATUS.md), 실행 규칙은 [AGENTS.md](../../AGENTS.md)를 따른다.
이번 문서 정리로 모델 설치·코드 구현·환경 설정·데이터 변경은 수행하지 않았다.

## 이미 적용한 부분

- 공식 현행 쟁점 검색: Ollama Qwen3 조문/항 벡터 + Kiwi 한국어 BM25 + 검증된 CITES GraphRAG.
- 두 벡터 질의와 첫 질의 BM25 병렬 실행, 가중 RRF, 제목/주 질의 후보 보존, 직접 조문 조회.
- Regex 명시 참조/수치 보호, 제한된 사전 Fuzzy 확장, 보호 후보 위치와 전체 후보를 보존하는 MMR.
- 쟁점별 근거 충족 Judge, 부족 쟁점 재검색, 서버 출처 ID·시행일·해시·원문 구간·주장 공개 검사.
- 동일 시행본의 원문·부모/항 색인 보정과 입력 이력, 그래프 정합 감사, 임베딩/XML 캐시.
- 운영자 LangSmith, 사용자 SSE 진행과 답변 당시의 근거 스냅샷 패널.

사용자 문서·과거 법령·유권해석은 공유 현행 BM25 대상이 아니다. 전용 Reranker는 없다.

## 개선 순서 제안

| 순서 | 제안 | 확인할 효과 |
|---|---|---|
| 1 | 개발에 사용하지 않은 전문가 정답/필수·무관 근거 holdout 확보 | 검색 순위와 세무 답변 정확성을 독립적으로 비교 |
| 2 | 전용 Reranker와 후보 풀 유지 | 질문과 닮았지만 주체·세목·요건이 다른 후보를 낮춤 |
| 3 | 요건·예외·위임 조문을 묶는 근거 구성, 토큰별 쟁점 예산 | 예외 누락과 일부 쟁점의 입력 예산 독점 감소 |
| 4 | 일반 상담의 사건일별 시행본·부칙 연결 | 과거 사건에 현행법만 검색하는 한계 보완 |
| 5 | 공식 예규·해석·신고 안내의 유형별 검색·채택 규칙 | 신고 절차·서류·실무 질문의 근거 범위 확대 |
| 6 | 질문 유형별 가중치·후보 수, 단계별 지연 최적화 | 유형별 관련성과 전체 응답 시간 개선 |

## 전용 Reranker의 구현안

### 모델과 실행

- 1차 시험 후보: `Qwen/Qwen3-Reranker-0.6B`. 한국어 세무 holdout 평가와 자원 측정 후 모델을 확정한다.
- 별도 Docker 서비스에서 FastAPI + Sentence Transformers 또는 공식 Transformers 추론을 사용한다. 모델은 시작할 때 한 번 로딩하고 배치 처리한다.
- 임베딩 Ollama `qwen3-embedding:4b`/v1과 생성·Judge OpenRouter `openai/gpt-6-luna`는 유지한다.
- 모델 revision·의존성·입력 구성 버전을 고정한다. Ollama와 GPU를 공유할 경우 동시 처리 메모리와 지연을 함께 측정한다.
- 참고: [Qwen 공식 모델/실행 문서](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B), [Sentence Transformers 재정렬 구조](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html).

### 연결 위치와 후보 관리

```text
BM25/벡터 → 출처 식별자 기준 RRF 통합 → 제한된 검증 Graph 보충
→ 쟁점별 Reranker → MMR/근거 선정 → 근거 충족 검사 → 생성/주장 검증
```

- 현재 `_search_issue_candidates()`는 각 검색 경로 15개를 RRF에서 8개로 먼저 줄인다. Reranker 앞에서 비교할 후보 풀을 유지하는 변경이 필요하다.
- 후보 30~40개·최종 8~12개는 실험 시작값이다. 후보 풀 확대와 Reranker 효과를 따로 비교하고, 무조건 후보 수를 늘리지 않는다.
- Graph 확장은 기존 상위 seed와 관계/본문 예산을 유지한다. 넓힌 후보 전체를 무제한 확장하지 않는다.
- 명시 요청 조문·필요한 예외/위임 근거를 보존한다. MMR은 재정렬 후 순위를 관련성 기준으로 사용하도록 연결하고 보호 후보 회귀를 확인한다.
- 재검색 결과도 같은 단계를 거친다. 원문 전용 정확 조회는 기존 정확 경로를 유지한다.

### 입력·출력 계약

- 평가 질의: 원 질문의 공통 사실관계와 현재 쟁점의 주체·세목·판단 사항. 모델이 만든 가정을 사용자 사실로 확정하지 않는다.
- 평가 문서: 법령명·조문·시행일과 관련 항/필요 맥락. 긴 조문은 원문 구조로 구간을 만들고 길이 제한·잘림 여부를 기록한다.
- 요청은 서버 후보의 ID/본문 목록, 응답은 ID/관련성 점수 목록이다. Reranker가 원문·출처·법적 결론을 작성하거나 변경하지 않는다.
- 응답 ID의 누락·추가·중복, 비수치/무한 점수, 모델/버전 불일치를 검사한다. 원본 스냅샷과 인용은 기존 서버 레코드를 사용한다.
- `retrieval_scores['rerank']`에 점수를 별도로 보존한다. 코사인·BM25·RRF와 척도를 섞거나 점수를 세무 정답 확률로 표시하지 않는다.

### 제안 파일·운영 모드

| 제안 대상 | 역할 |
|---|---|
| `services/reranker/` | 모델·배치 추론·`/rerank`·상태 확인 API |
| `app/services/search/rerank_service.py` | HTTP 호출·응답 검사·점수 연결·fallback |
| `app/services/search/hybrid_search_service.py` | 후보 풀/후속 근거 검사 연결 |
| Docker Compose·`config.py` | 서비스·모델 캐시·자원·시간 제한·모드 |

위 새 디렉터리/API와 `off / shadow / active` 모드는 아직 구현하지 않았다. 신규 환경변수 이름도 미확정이다.
`dev/docker-up-wsl.sh`의 기존 `RERANK_MODEL` 모델 확인 잔여 코드는 Reranker 실행 경로가 아니다.

- `off`: 기존 검색.
- `shadow`: 기존 검색으로 답변하고 재정렬 전후만 비교 기록.
- `active`: 채택된 재정렬을 실제 채팅 경로에 적용.
- 장애·시간 초과·잘못된 응답은 기존 순서로 돌아가고 원인을 기록한다. 출처·시점·근거 충족·주장 공개 검사는 계속 적용한다.
- LangSmith에 후보 ID/전후 순위/모델/점수/지연/fallback을 남긴다. 사용자에게는 기존 근거 패널의 채택 자료를 제공한다.

## 검증과 적용 조건

- 검색: 쟁점별 필수 근거 확보, MRR/nDCG, hard negative 채택, 잘못된 세목·주체·연도 혼입.
- 답변: 쟁점 누락, 근거/결론 일치, 요건·예외, 근거가 있는데도 보류한 비율, Judge 오답 통과/정상 답변 차단.
- 운영: cold/warm 및 전체 P50/P95, 동시 요청, Ollama와의 자원 경합, 오류·fallback, 생성/Judge 호출 횟수.
- 기존 39문항은 개발 회귀에만 사용하고 독립 holdout을 별도로 검수한다. 코드 회귀·실제 모델·웹 표시 검증을 세무 정답 검수와 구분한다.
- 독립 평가 기준·허용 지연·배포 설정을 정한 뒤 shadow → 비교 → active로 적용한다. 현재 문서는 이 승격을 수행하거나 승인한 기록이 아니다.

## 1. 공식 회답 정답셋 — 구현(2026-11-07), 실행 전

- **무엇**: DB의 법제처 법령해석례마다 질의요지·공식 회답·이유가 있다. 회답을 정답으로 쓰므로 전문가가 필요 없다.
  `evaluation/build_interpretation_gold.py` → `evaluation/datasets/interpretation_gold.json`.
- **지금도 유효한지**: 회답이 기대는 조문의 **인용한 항**이 회신일부터 오늘까지 같은 글이면(과거 법령 보관소로 대조, 개정 표시 무시)
  `unchanged`다. 바뀐 경우는 현행법 평가에서 뺀다.
- **유출 차단**: 평가 중에는 그 해석례를 검색에서 숨긴다(`hybrid_search_service.EXCLUDED_INTERPRETATIONS`, 서비스에서는 비어 있음).
- **개발·시험 분리**: 해석 번호 해시로 고정(약 6:4). 조정·보정은 개발용으로만, 시험용은 판정에만 쓴다.
- **평가**: `evaluation/gold_eval.py`가 서비스 경로로 답하고, 판정 모델이 공식 회답과 결론을 비교한다(일치·부분·반대·결론 없음).
  틀린 결론 비율, 답변 제공률, 핵심 조문 회수, 위험 신호, 수치 검사 신호를 기록한다. `--yes-paid` 없이는 계획만 보인다.
- **남은 일**
  1. 개발용 실행(유료, 계획 출력 기준 문항당 약 7~11회 호출). Neo4j를 켜고 서비스 설정 그대로.
  2. 생성과 다른 계열의 판정 모델 지정(`GOLD_JUDGE_MODEL`) — 지정하지 않으면 결과에 "같은 계열"로 표시된다.
  3. 판정 20건을 사람이 다시 보고 판정 일치율을 기록한다.
  4. 해석례를 Open API로 더 모은다(정답셋 전용 파일, 서비스 검색 대상에는 넣지 않음 → 유출 없음). 국세청 질의회신은 이용 조건 확인 후.

## 2. 측정된 실패 원인을 데이터·구조로 고치기 — 일부 구현

| 작업 | 상태 | 내용 |
|---|---|---|
| 위임 조문 자동 결합 | 구현(기본 켬) | 쟁점 검색 결과의 법률 조문이 "대통령령으로 정하는"을 쓰면 그 조문을 "법 제N조"로 인용하는 시행령 조문을, 시행령이 부령에 맡기면 시행규칙 조문을 질문과 가까운 순으로 2개까지 붙인다(`SEARCH_DELEGATION_*`). 조문 검색 평가 점수는 그대로였다(정답 라벨이 대부분 법률 조문). 효과는 정답셋 실행의 "근거 부족" 판정 감소로 확인한다 |
| 수치 확정 검사 | 구현(신호) | 주장에 쓴 세율·금액 기준·기간이 인용 원문이나 질문에 없으면 `figure_not_in_source`(100분의 20=20%, 4천800만원 등 표기 정규화, 이미지 표가 있는 원문의 세율은 제외). 정답셋 실행에서 Judge가 지지한 주장에 붙은 비율을 재고, 낮으면 `CLAIM_FIGURE_GATE=block`으로 올린다 |
| 공식 사례가 있는 요건의 결정표 | 미구현 | 정답셋 실행에서 자주 틀리는 요건 중 공식 판정 사례가 있는 것만 계산기처럼 코드로 옮긴다 |
| 실패 분류 | 실행 대기 | 틀리거나 보류된 문항을 검색 누락(핵심 조문 미회수), 근거 부족 판정, 생성 오류, 판정 통과 오류로 나눠 가장 큰 원인부터 고친다 |

## 3. 보류 기준을 정답셋으로 보정 — 구현, 보정 전(효과 없음)

- **위험 점수**: 검증 보고서에 이미 있는 값만 쓴다(근거 부족 쟁점 비율, 보류된 주장 비율, 답 못 한 쟁점, 신호가 붙은 주장, Judge 누락 쟁점).
  호출이 늘지 않는다(`app/services/answer_risk.py`). 매 답변의 `verification.risk`에 기록된다.
- **보정**: `evaluation/abstention_calibration.py`가 개발용에서 틀린 답을 가장 잘 가르는 점수를 고르고(AUC), conformal risk control로
  "알림 없이 나간 답 중 틀린 결론 비율 ≤ α"를 만족하는 가장 큰 임계값을 정한다. 시험용은 확인에만 쓴다.
- **적용**: `ANSWER_RISK_THRESHOLD`가 비어 있으면 아무 영향이 없다. 정하면 임계값을 넘는 답에 "확인 필요" 안내를 붙이거나(`notice`,
  기본) 보류한다(`hold`). 보장 범위는 "공식 질의와 같은 종류의 질문"이며 모든 질문에 대한 보장이 아니다.
- **남은 일**: 정답셋 개발용 실행 → 보정 → 시험용 확인 → 설정 적용. 개발용 문항 n개로는 α ≥ 1/(n+1)만 가능하다.

## 진행 순서

1. D1 배포 마무리(무료).
2. 정답셋 개발용 실행(유료, 실행 전 호출 수 확인) → 실패 분류 → 수치 검사 승격 판단.
3. 보류 기준 보정 → 시험용 확인 → 설정 적용.
4. 가장 큰 실패 원인부터 데이터·구조 수정(2번 표), 결정표는 공식 사례가 있는 요건만.
5. A1·A2, C1·C2.
6. 필요할 때 D2.

각 단계를 마치면 결과를 CURRENT_STATUS에, 채택·기각을 DECISIONS에 기록하고 이 문서에서 끝난 항목을 지운다.

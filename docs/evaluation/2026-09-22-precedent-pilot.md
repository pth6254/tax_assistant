# 판례 기반 채팅 품질 실험 — 2026-09-22

## 실행 범위

- 수집한 대법원 판례 5건의 사실관계·쟁점·구법 적용 범위로 질문을 작성했다. 판결 결론과 판결요지는 답변 생성기에 제공하지 않았다.
- 현재 Ollama `qwen3.5:9b`의 실제 `process_chat` 경로로 도구 선택, 법령 검색, 답변 생성, 인용 검증을 실행했다. 생성 컨텍스트는 4,096이다.
- 웹에서 정답 판결을 가져오는 누출을 피하려고 웹 검색을 끄고, 새 임의 사용자 UUID 및 빈 대화 기록을 사용했다. 대화 저장도 차단했다. HTTP·인증·SSE·브라우저 종단간 실험은 아니다.
- 실행 컨테이너의 **GRAPH_RAG_ENABLED=false**를 관측했다. 과거 문서의 활성화 기록과 다르다. 설정은 변경하지 않았으며 **Graph RAG 성능 실험 또는 A/B 비교가 아니다.**
- Judge는 수집한 공식 판결요지 전체와 실제 답변을 비교했다. 원문 본문 전체·관련 후속심까지 평가한 것은 아니다. 평가 질문/루브릭은 draft를 유지하며 사람의 법적 정답 인증으로 승격하지 않았다.
- LLM Judge도 동일 모델을 사용했다. 생성과 Judge 실행 사이에 정답 전달을 분리했지만 자기평가 편향은 남는다.

## 원인: 확인된 것과 추가 확인할 것

1. **조회 실패 후에도 정상 답변 생성으로 진행**: `chat_service._fetch_rag_and_web_context`가 법령·문서 도구의 실패 여부와 무관하게 오류 안내문을 컨텍스트로 반환한다. 이후 최종 생성이 진행돼 법적 근거가 없는 상태에서 단정적 설명이 나왔다. 도구 실패 시 재질문·판단 유보 또는 검증된 일반 검색 fallback을 명시적으로 선택해야 한다.
2. **구법 질문과 검색 근거의 시점 불일치**: 예식장 사례 검색 컨텍스트에 2023년 개정 내용이 포함됐다. 질문의 구법 버전을 확보했는지 확인하고, 확보하지 못하면 현재 자료로 과거 법률관계를 단정하지 않도록 해야 한다.
3. **인용 경고는 오답 차단이 아님**: 검증 불가 인용에 경고를 붙였지만 잘못된 결론·가상 해석은 본문에 남았다. 조문 존재 확인과 주장 내용의 지지 여부를 별도로 평가해야 한다.
4. **컨텍스트 예산 계측 필요**: 수수료 사례 검색 원문은 8,364자, 생성 설정은 4,096 토큰이다. 단위가 달라 이 수치만으로 잘림을 확정할 수 없다. 최종 프롬프트 토큰수·실제 prompt_eval_count·출력 종료 사유를 기록해야 한다.
5. **Judge도 오류를 낸다**: 첫 사례의 시점 항목을 pass 처리하면서 판결과 반대되는 해석이 판결 취지와 일치한다고 설명했다. 두 번째 사례에서도 판결 내용을 잘못 읽은 설명이 나왔다. 증거 ID 검증은 발췌의 존재만 확인하고 의미의 정확성은 보장하지 않는다.

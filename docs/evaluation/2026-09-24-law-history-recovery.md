- 독립 `law-history-worker`를 history profile로 추가. 채팅 API를 재시작하지 않았다.
- 기존 2,898개를 삭제/초기화하지 않고 pending만 재개했다. run 5에서 192개 추가 후 자동 검수 구성 적용을 위한 컨테이너 재생성, run 6에서 나머지 2,310개 추가를 확인했다.
- 이전 run 4/5는 다음 worker가 DB 잠금을 획득한 뒤 interrupted로 정리했다. 재생성 후 중단 지점 이어받기를 실제 확인했다.
- `on-failure:3` 제한 재시작 정책을 설정했다. 비정상 종료 자동 재시작 자체를 별도 강제 장애로 시험한 것은 아니다. 이번 관측의 자동 재시작 횟수는 0이다.
- status는 저장 상태와 잠금/heartbeat 기반 observed_status를 구분한다. 잠금이 없으면 interrupted, 잠금이 있으나 180초 이상 진행이 없으면 unresponsive로 관측한다. 조회만으로 DB 기록을 수정하거나 잠금을 해제하지 않는다.
- PC/WSL/Docker 자체 종료 후 자동 부팅·재개를 보장하지 않는다. 환경 복구 후 `bash dev/law-history-wsl.sh start`로 명시 재개한다.

# 과거 법령 임베딩 완료 후 검증 — 2026-09-25

## 범위와 방법

- 실행 중인 `tax_backend`와 PostgreSQL·Neo4j·Windows Ollama를 사용했다. `evaluation/history_retrieval_pilot.py`는 사용자 대화 기록을 읽거나 쓰지 않는다.
- 저장 상태를 DB에서 확인하고, 과거 법령 관련 회귀 테스트 31개, 실제 의미 검색 3개, 검색 실패 유보 2개, 실제 GraphRAG 채팅 스모크를 실행했다.
- `evaluation.history_index_audit`로 과거 스냅샷 5,400개의 PostgreSQL 원본 소속과 Neo4j `HAS_UNIT` 관계를 전수 대조했다.

| 검증 | 결과 |
|---|---|
| 벡터 저장 | 127,838/127,838, 실패 0, 2,560차원 일치, 모델 규격 1종 |
| 텍스트-청크 매핑 누락 | 0/90,935 |
| 과거 검색·답변·수집 회귀 테스트 | 31 passed |
| 의미 검색 소규모 진단 | 3/3 기대 조문 top-5 포함; 세 질의 모두 첫 번째 결과가 기대 조문 |
| 없는 조문·연도만 지정한 요청 | 2/2 유보 |
| Neo4j 소속 전수 감사 | 5,400/5,400 일치, 오류 0, 명시적 `MENTIONS` 86,552 |
| 실제 GraphRAG 채팅 스모크 | 지방세징수법 버전 1063 제16조에서 지방세기본법 버전 1012 제75조 근거 1개 추가, 원문 인용 포함 응답 생성 |

의미 검색 진단은 소득세법 버전 529(납세의무 → 제1조), 지방세기본법 버전 1012(양도담보권자의 물적 납세의무 → 제75조), 지방세징수법 버전 1063(양도담보권자로부터 징수하는 절차 → 제16조)를 사용했다. 질의는 저장 원문·제목에서 구성한 표본이며 독립 검수 정답셋이 아니다.

첫 진단 실행에서는 GraphRAG가 추가한 다른 법령 버전의 근거까지 원래 버전과 같아야 한다는 잘못된 판정 기준 때문에 1건이 실패했다. 기본 검색 결과와 그래프 추가 결과를 구분하도록 진단 코드를 수정한 후 같은 5건을 재실행해 모두 통과했다. 제품 검색 결과의 오류는 아니었다.

## 해석과 다음 검증

이번 결과는 저장 무결성, 일부 버전의 실제 검색 연결, 그래프 소속 및 응답 경로가 작동한다는 근거다. 전체 5,400개 버전의 의미 검색 품질이나 법적 정답률을 나타내지 않는다. 다음에는 독립적으로 검수한 질문·정답 조문·혼동 조문(hard negative)을 여러 법령·개정 시점별로 마련해 Recall@K, 인용 정확도, 법적 적용 시점과 답변 오류를 따로 평가해야 한다.

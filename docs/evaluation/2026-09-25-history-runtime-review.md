## 점검 범위

실행 중인 백엔드에서 읽기 전용 DB 조회와 서비스 함수 호출로 재현했다. 대화 함수 검증에서는 `_fetch_history`/`_save_history`를 메모리 대역으로 교체해 사용자 대화에 쓰지 않았다. 생성 실패·후속 질문 경로 검증은 명시적으로 예외를 주입했다. 법적 결론의 정확도 평가나 전체 서비스 보안·부하 감사는 아니다. 제품 코드와 데이터 수정 없이 발견 사항을 기록한다.

관련 기존 테스트는 `docker exec tax_backend pytest -q tests/test_history_search.py tests/test_history_answer.py tests/test_law_history.py`에서 31 passed였다. 아래 사례가 통과 테스트 범위 밖에 있음을 확인했다.

## 2. P1 — 중복 번호가 항·호 본문 조회를 깨뜨림

- 위치: `app/services/law/history_parser.py:74`, `app/services/law/structure_parser.py:96`.
- 실제 저장 본문: `제59조의4(특별세액공제)\n①\n① 근로소득이 있는 거주자...`, 호도 `1.\n1. 기본공제대상자...` 형태다.
- 재현: `법령버전 309 제59조의4 제1항 제1호 원문`은 해당 호가 본문에 존재하는데도 없다고 반환했다. 제1항 대조 결과의 text는 `①` 한 글자였고, 뒤의 두 번째 제1항 블록에는 실제 본문과 제1호가 있었다.
- 규모: `①\n①` 패턴이 원본 조문 발생 행 583,010개, 고유 조문 본문 53,466개에서 확인됐다. 이 수는 중복 패턴의 개수이며 모든 조항의 개별 오답을 검사한 수가 아니다.
- 원인: XML의 항번호·항내용 및 호번호·호내용을 중복 여부 없이 이어 붙이고, 본문 조회기는 첫 번째 일치 블록을 선택한다.
- 개선: 보존한 XML/구조 트리로 항·호·목을 직접 해석하거나 번호 중복을 제거한 정규 본문을 별도로 만든다. 번호만 있는 블록을 유효한 항으로 인정하지 않는 검증도 필요하다. 기존 원본 스냅샷은 보존하고, 본문 규격을 변경할 경우 버전을 올려 영향받는 파생 색인만 재생성한다.

## 3. P1 — 질문 대상 조문이 길면 그래프의 다른 법령만 답변 입력에 남음

- 위치: `app/services/search/history_search.py:104`, `app/services/law/history_answer.py:49`.
- 재현: `법령버전 309 제59조의4 제1항을 설명해줘`.
- 결과: 지정 항의 존재만 검사하고 조 전체를 반환한다. 소득세법 원문 근거는 메타데이터 포함 13,353 bytes여서 10,000-byte 입력 예산에서 제외됐다. 대신 그래프가 추가한 조세특례제한법 제122조의3(4,919 bytes)·제95조의2(2,885 bytes)만 선택됐다.
- 생성 함수는 예외 대역으로 교체했다. 이 점검은 실제 모델의 오답을 관측한 것이 아니라 실제 자료 선택과 답변 근거 목록에서 질문 대상이 사라짐을 확인한 것이다.
- 개선: 2번을 고친 뒤 요청 항·호·목의 검증된 본문을 우선 사용한다. 질문 대상 근거를 필수로 확보하고, 남는 예산에 관련 근거를 추가한다. 필수 근거를 담지 못하면 다른 법령만으로 설명을 생성하지 않도록 한다.

## 운영 및 평가 후속

- `history_index.py:71`은 실패 행을 기본 재개에서 제외하고, Compose는 `all`을 재시작할 뿐 `--retry-failed`를 붙이지 않는다. 실제 8개 ReadTimeout은 수동 재시도로 해결했다. 제한된 일시 오류 재시도와 진행 시각/진행 정지 탐지, 원인별 오류 집계가 필요하다. 현재 저장 결과는 127,838/127,838, 실패 0이다.
- 이전 5,400건 감사는 원본과 그래프의 소속·해시 일치 검증이다. 동일 파서가 만든 문자열이 일치해도 2번의 항·호 의미적 분할은 틀릴 수 있다. 번호 중복, 복합 의도, 긴 조문, 대화 후속 질문, 법령명 충돌을 평가에 추가해야 한다.
- 수정 권장 순서: 의도 분기와 항·호 파싱 → 질문 대상 근거 보존 → 대화 시점 유지 → 입력 충돌/실패 표시 → 배치 복구 및 독립 정답셋 확대.
